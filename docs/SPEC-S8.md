# S8 规格：不可逆删除

> **状态：已实现。** 本切片覆盖 `ADR-0012` 的"只移动、不删除"，由 `ADR-0014` 授权。

---

## 0. 与 ADR-0012 的关系

`ADR-0012` 曾把边界划在"可以移动、不可以删除"。S8 **覆盖**它：现在可以删除。

`--quarantine` 仍然存在，并且**仍然是推荐做法** —— 它可恢复。删除只是给
"我确认这些副本不需要了"这个场景提供的能力。

## 1. 五重授权

删除要求以下条件**同时**成立，缺一条就以退出码 1 拒绝：

| # | 条件 | 防的是什么 |
|---|---|---|
| 1 | `--apply` | 默认不执行任何改动 |
| 2 | `--delete` | 明确声明要删除而不是移动 |
| 3 | `--confirm-delete DELETE` | **防止从 shell 历史里误触** —— 必须逐字打出 `DELETE`，大小写敏感 |
| 4 | `--manifest FILE` | 必须指明审计清单写到哪；路径已存在则拒绝（退出码 4） |
| 5 | TTY 上逐条确认，或非 TTY 下显式 `--yes` | 防止无人值守时误删 |

第 3 条是最关键的一条。`--delete` 单独躺在 shell 历史里被按一下回车就是灾难；
要求打出一个完整的词，强制这是一次**有意识**的操作。错误信息会直接告诉你要打什么。

## 2. 为什么删除必须写审计清单

移动模式下，隔离目录本身就是记录。删除模式下**什么都不会留下**，所以
`--manifest` 不是一个可选项，而是唯一的留痕：

- 在任何删除之前写入
- 记录每个动作的路径、体积、sha256、保留项
- 拒绝覆盖已存在的文件（不让你无意中抹掉上一次的记录）

## 3. 删除前的复核（与移动相同，但后果更重）

执行每个动作之前重新校验，任一不通过即**拒绝该动作**并继续处理其余动作：

1. 路径仍在扫描根之下、不在 `.git` 等元数据目录内、不是符号链接、仍是普通文件
2. 大小与 sha256 与计划完全一致
3. **要保留的那一份仍存在，且 sha256 与计划一致** ← 删掉之后无可挽回，这条是底线

## 4. 技术实现

删除只用一次 `Path.unlink()`：

- **不经过 shell** —— 没有注入、没有通配符展开、没有 `rm -rf` 的风险
- **不递归** —— 调用前已确认目标是普通文件，且代码从不作用于目录
- **无后门** —— `apply.py` 中只有 `_unlink` 这一处调用点，全项目仅此一处

## 5. 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常 |
| 1 | 参数错误（含缺令牌、令牌错误、缺 `--manifest`） |
| 2 | 扫描根不存在或不可读 |
| 3 | 执行中有动作被拒绝 |
| 4 | 审计清单路径已存在，或隔离目录不可用 |

## 6. 明确不做

- 递归删除目录（`shutil.rmtree` 之类）
- 删除目录 —— 只删普通文件
- 移入系统回收站
- 任何绕过确认令牌的"后门"或环境变量开关
- 先删再记（清单一定先落盘）

## 7. 验收清单

- [x] 只给 `--delete` 不给令牌 → 退出码 1，**文件完好**
- [x] 令牌大小写错误（`delete`）→ 退出码 1，**文件完好**
- [x] 缺 `--manifest` → 退出码 1，**文件完好**
- [x] `--manifest` 指向已存在文件 → 退出码 4，**文件完好**
- [x] `--quarantine` 与 `--delete` 同时给出 → 退出码 1，**文件完好**
- [x] 完整授权后才真正删除，且**保留的那一份仍在**
- [x] 审计清单在任何删除之前写入（清单里记录的路径此时已不存在）
- [x] 保留项消失 / 保留项变化 / 目标变化 / 目标在根外 → 拒绝且**文件仍在**
- [x] 用户拒绝确认 → 文件原地不动
- [x] 空计划也会写清单
