# 决策记录（ADR）

> **这个文件怎么用**：只记录**已经拍板**的决策和当时的理由。
> 规则是**只追加，不修改旧条目**。要推翻某个决定，就新增一条 ADR 并标注
> "取代 ADR-XXXX"，而不是回头改历史。这样三个月后还能看懂当初为什么这么选。

## ADR-0001 项目独立建仓，路径 `~/projects/homecheck`

- **状态**：已接受
- **日期**：2026-09-13
- **背景**：需要一个能跑通完整协作流程的练手项目。当前可用位置有两个问题：
  DSH 工作区（`<工作区路径>`）是 DeepSeek Harness 自身的代码库；
  而 home 目录本身也是一个 git 仓库，只有 1 个提交、大量文件处于未跟踪状态。
- **决定**：homecheck 独立建仓，路径 `~/projects/homecheck`，与上述两个仓库都无关。
- **理由**：练手项目不应污染任何现有仓库；独立仓库可以随时整体回滚甚至直接删掉。
- **后果**：
  - ✅ 隔离干净，搞砸了删目录即可，不影响任何现有工作
  - ⚠️ 需要单独初始化 git（**尚未执行**，等待明确批准）
  - ⚠️ 该路径在当前 DSH 文件沙箱之外，每次写入需要单独授权

## ADR-0002 技术栈：Python 3 + 标准库优先

- **状态**：已接受
- **日期**：2026-09-13
- **背景**：需要一个直接在本地文件系统上工作的命令行工具。
- **决定**：使用 Python 3.12（`python3`）。
  **标准库优先**：`pathlib` / `os` / `hashlib` / `argparse` / `unittest`。
  运行时零第三方依赖。
- **理由**：
  - 本机现成可跑，不需要安装任何东西
  - 标准库完整覆盖扫描、哈希、CLI 解析、测试这些需求
  - 依赖越少，长期可维护性越好，也避开供应链风险
- **后果**：
  - ✅ `git clone` 下来就能跑，没有环境搭建步骤
  - ✅ 测试用标准库 `unittest`，不需要 pytest
  - ⚠️ 进度条、彩色输出这类体验功能要自己写，或者干脆放弃
- **已否决的备选**：
  - Node / TypeScript —— 本机虽有 node 环境，但做文件系统工具标准库不如 Python 顺手
  - `click` / `rich` 等第三方库 —— 当前规模用不上，需要时再议

## ADR-0003 文档先行：M0 定稿前不写代码

- **状态**：已接受
- **日期**：2026-09-13
- **背景**：本项目同时是协作流程的训练场。主要风险是**方向漂移**和**范围蔓延**，
  而不是编码难度。
- **决定**：`PRODUCT.md` 第 8 节的开放问题（Q1–Q7）全部确认之前，不写任何功能代码。
- **理由**：一旦开始写代码，尚未确定的边界会被实现细节反向锁死，那时再改成本高得多。
- **后果**：前期看起来慢，但方向的最终控制权始终在项目所有者手里。

## ADR-0004 默认只读；写操作需要三重授权

- **状态**：已接受（2026-09-13）
- **日期**：2026-09-13
- **背景**：这是整个项目风险最高的部分 —— 一个能删除用户文件的工具。
- **决定**：工具的默认行为是**零写入**。任何改动文件系统的操作，
  必须同时满足三个条件才允许发生：
  1. 显式传入 `--apply`
  2. 逐个动作人工确认
  3. 执行前生成备份清单（记录原路径与去向）
- **理由**：把"误伤"从"可能发生"变成"必须三次主动同意才会发生"。
- **后果**：
  - ✅ 默认使用绝对安全
  - ⚠️ 批量清理会变得啰嗦 —— 这是**故意**的

## ADR-0008 报告只输出到 stdout，不写文件（S3）

- **状态**：已接受（2026-09-13）
- **背景**：`--json` / `--markdown` 需要一个去向。写成文件更方便，但会
  让"默认零写入"的承诺出现例外。
- **决定**：`--json` 与 `--markdown` **只写 stdout**，不提供输出文件选项。
  落盘由用户自行重定向：`homecheck . --json > report.json`。
- **理由**：CONVENTIONS §6 规定 `apply.py` 之外禁止写文件（含临时文件）。
  保持这条不变量，比多一个便利选项更有价值。
- **后果**：
  - ✅ "不传 `--apply` 就零写入"这条承诺至今没有任何例外
  - ⚠️ 用户要记一次 shell 重定向

## ADR-0009 建议输出量必须封顶（实跑后追加）

- **状态**：已接受（2026-09-13）
- **背景**：首次实跑 `~/code` 发现 **2000+ 组重复文件**（`node_modules` 噪音），
  建议引擎逐组输出，报告被彻底刷屏，不可用。
- **决定**：
  1. 建议里最多为 **5 组**重复文件附删除命令，其余合并为一条摘要（D13）
  2. 新增 `--min-duplicate-bytes`（默认 1），由用户自行抬高查重门槛（D14）
  3. **不**擅自修改默认门槛 —— Q4 只说了排除空文件
- **理由**：工具在真实数据上不可用，等同于没做。但改变默认语义属于产品决策，
  必须留给所有者。
- **后果**：`~/code` 的报告从数千行降到 60 行。默认行为仍保留全量查重。

## ADR-0010 S5 遵循 Q5：只生成执行计划，不执行改动

- **状态**：已接受（2026-09-13）
- **背景**：`PRODUCT.md` 内部存在冲突 ——
  - **G7**：显式 `--apply` + 逐条确认 + 备份清单，三者齐备才可能移动/删除
  - **Q5**：v1 只输出命令，工具自身不执行删除
- **决定**：S5 遵循 **Q5**，即只产出可复核的「执行计划」，不执行任何动作。
  G7 中"真正执行"的部分**未实现**，留待所有者明确授权后另开切片。
- **理由**：
  1. Q5 是针对"清理方式"专门拍的板，比 G7 的概述更具体
  2. Q5 确认时间更晚
  3. 不执行的工具无法销毁数据 —— 冲突时向安全侧倾斜
- **后果**：
  - ✅ 工具至今没有任何能改动文件系统的代码路径（`apply.py` 也只读）
  - ⚠️ G7 的承诺目前**只兑现了一半**：有计划与审计清单，没有执行
  - ⚠️ 若所有者要真正的 `--apply`，需新增 ADR 覆盖本条
