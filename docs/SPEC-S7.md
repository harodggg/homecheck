# S7 规格：执行（把冗余副本移入隔离目录）

> **状态：已实现。** 本切片部分覆盖 Q5，理由见 `DECISIONS.md` 的 `ADR-0012`。

---

## 0. 对 Q5 的覆盖范围

Q5（v1 清理方式）的原文是：**「只输出命令，工具自身不执行删除」**。
S7 对它做了**部分**覆盖，边界划得很清楚：

| Q5 的约束 | 现在的状态 |
|---|---|
| 工具自身不执行**删除** | ✅ **仍然成立** —— 工具从不删除任何东西 |
| v1 只输出命令 | ⚠️ **部分覆盖** —— 现在也可以"移动"（需三重授权） |

**工具新增的能力只有"移动"，没有"删除"。** 不可逆的 `rm` 仍然只打印给用户。

## 1. 三重授权（兑现 G7）

G7 要求"显式 `--apply` + 逐条确认 + 执行前备份清单，三者齐备"。对应实现：

| G7 条件 | 实现 |
|---|---|
| 显式 `--apply` | `--apply` 开关，默认关闭 |
| 逐条确认 | `--quarantine DIR` 必须指定，且默认在 TTY 上逐条询问 `[y/N]` |
| 执行前备份清单 | `<quarantine>/manifest.json` 在**任何移动之前**写入 |

非交互环境（无 TTY）下执行，必须**显式**给出 `--yes`，否则直接拒绝并返回退出码 1。

## 2. 为什么是"移动"而不是"删除"

- **移动可逆**：隔离目录保持相对扫描根的目录结构，可以原样移回（已实际演练）
- **删除不可逆**：手滑一次无法挽回
- G7 原文是"移动/删除"，S7 实现的是前一半

## 3. 执行前复核（防止计划过期）

计划生成到执行之间可能隔了很久，文件系统早已变化。因此**每个动作执行前**重新校验：

1. 路径仍在扫描根之下、不在 `.git` 等元数据目录内、不是符号链接、仍是普通文件
2. **大小与 sha256 与计划完全一致**
3. **要保留的那一份仍存在，且 sha256 与计划一致** ← 最关键，否则移走就等于丢数据

**任一不满足 → 拒绝该动作**，记录原因并继续处理其余动作（不整体中断）。

## 4. 审计清单

`<quarantine>/manifest.json`，`schema_version: 1`：

```
{
  "schema_version": 1,
  "tool": "homecheck",
  "created_at": "...",
  "root": "...", "quarantine": "...",
  "action_count": int, "total_bytes": int, "truncated": int,
  "actions":  [ {kind, path, size, digest, keep, reason} ],
  "refusals": [ {path, reason} ]
}
```

写入时机是**移动之前** —— 即使中途崩溃，也有一份"本来要做什么"的记录。

## 5. 恢复方式

隔离目录保留相对路径，所以：

```bash
cd <quarantine> && find . -type f ! -name manifest.json \
  -exec sh -c 'mkdir -p "<root>/$(dirname "$1")" && mv "$1" "<root>/$1"' _ {} \;
```

这条已在一次性临时目录上实际演练过，3 个文件全部移回。

## 6. 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常（含"计划为空、无事可做"） |
| 1 | 参数错误（含缺 `--quarantine`、非 TTY 却没用 `--yes`） |
| 2 | 扫描根不存在或不可读 |
| 3 | 执行中有动作被拒绝（复核未通过或移动失败） |
| 4 | 隔离目录已被占用或非空 |

## 7. 明确不做

- **不可逆删除**（`rm`）—— 只打印命令
- 递归删除（任何情况下都不用 `-r` / `-rf`）
- 移入系统回收站
- 冻结/快照文件内容（隔离目录本身就是保留副本）
- 自动重试失败的动作
