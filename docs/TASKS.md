## 已知限制

| 限制 | 影响 | 缓解 / 后续方向 |
|---|---|---|
| 全量查重的耗时与数据量成正比 | 本机 home 有 **3,360,177 文件 / 352.03 GB**，全量查重 40 分钟未完成 | `--skip-duplicates`、`--min-duplicate-bytes`、`--max-depth`；根治需分桶落盘/流式（见 ADR-0013） |
| 扫描的内存随文件数线性增长 | 336 万文件约 1.2 GB | 已实测 `slots=True` 仅省 9%，未采纳；根治需不驻留全部文件明细 |
| 目录递归深度受 Python 递归上限约束 | 理论上超过约 1000 层会报错 | 实测 60 层正常；macOS 路径长度上限通常先触发 |
| 不处理模糊重复 | 相似但不完全相同的文件不会被发现 | 属非目标（`PRODUCT.md` N4 精神） |
| **删除不可恢复** | S8 的 `--delete` 是真正的销毁，审计清单只能事后追溯、不能还原 | 默认应使用 `--quarantine`；删之前先移动、确认无误再清理隔离目录 |

## 性能基线（Q7，见 ADR-0013）

| 场景 | 规模 | 耗时 |
|---|---|---|
| `~/Github`，限深 3 层，含全量查重 | 25,507 文件 / 1.52 GB | **0.26 s** |
| 完整 home，仅扫描 | 3,360,177 文件 / 302,008 目录 / **352.03 GB** | **114.09 s** ✅ 达标 |
| 完整 home，含全量查重 | 同上 | 40 分钟未完成（已由数据量解释） |

**Q7 目标**：扫描阶段 350 GB / 336 万文件 ≤ 3 分钟 —— 实测 114 s，已达标。
查重阶段**不设时限**（耗时由数据量决定，不由实现质量决定）。
